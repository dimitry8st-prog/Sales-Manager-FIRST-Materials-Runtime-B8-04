## Что делает компонент

Компонент проверяет запрос и права пользователя, учитывает остановку автоматизации и передачу человеку, получает утверждённый каталог и материал через доверенные зависимости, сохраняет материал и готовит действие. Сам компонент не отправляет письма и не подключается к рабочей базе.

Публичная точка входа: `create_service(ports).execute(operation, request)`.

Операции: `prepare` и `prepare_initial`. Точные требования и границы зависимостей находятся в исходном пакете.

## Что есть в опубликованном коде

- Строгая проверка полей запроса и scope.
- Проверка идентификаторов и канонического UUID кампании.
- Проверка аутентификации, capability и принадлежности клиенту.
- Работа через переданный контекст транзакции.
- Блокировка автоматизации при STOPPED / HUMAN / HANDED_OFF.
- Проверка ответа каталога, версии и признака утверждения.
- Проверка события, материала и допустимых фактов.
- `materials.save` с проверкой `material_ref` и откатом при плохом ответе.
- `dispatch.propose` для `PRODUCT_INFO`, `PRESENTATION` и `INITIAL_OUTREACH`.
- `prepare_initial`: квалификация, материал первого контакта, сохранение и очередь. `NEEDS_REVIEW` и `NOT_QUALIFIED` блокируют сохранение.
- Повтор того же запроса возвращает `REPLAY`. Изменённый запрос с тем же идентификатором возвращает `CONFLICT`.

Компонент не вызывает провайдера отправки. Не используйте его для реальных писем или рабочей базы.
