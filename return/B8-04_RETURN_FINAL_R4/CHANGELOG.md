# CHANGELOG — B8-04 R4

## Исправление финальной проверки

- После успешного `dispatch.propose`, но до replay и commit, повторно читаются
  authority и каталог.
- STOPPED/HUMAN/HANDED_OFF имеет безопасный приоритет и даёт `BLOCKED`; смена
  контрактных `version`/`revision` даёт `STALE`.
- Отказ покидает транзакционный контекст исключением. Поэтому промежуточная
  материализация, save, proposal и replay текущего запроса откатываются.
- Ранее зафиксированный другой транзакцией STOP не восстанавливается старым
  снимком: проверка только читает состояние, а PostgreSQL scoped lock задаёт
  порядок транзакций.

## Закрытие обязательных сценариев CP2

- Добавлен отдельный process worker с управляемыми барьерами в PostgreSQL.
- Проверен настоящий kill worker до commit после выполнения SQL: ни staging,
  ни save/proposal/replay не зафиксированы.
- Проверен commit до потери ответа: после kill новая служба возвращает REPLAY
  без повторных save/propose.
- Проверены независимые STOP/config-сессии, ожидание scoped lock, порядок
  commit и финальное состояние БД.
- Барьеры имеют ограниченные таймауты; `sleep` не является доказательством
  порядка.

Контракты, fixtures, runners, reference_source/reference_d1 и общий runtime не
изменялись.
