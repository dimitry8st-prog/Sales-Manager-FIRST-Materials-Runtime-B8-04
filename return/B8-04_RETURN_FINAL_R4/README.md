# B8-04 R3 — возврат исполнителя R4

Этот архив закрывает два замечания приёмки к R3: финальную проверку состояния
после dispatch и недостающие аварийно-конкурентные сценарии CP2.

## Фактический итог

- Новые проверки на исходном стенде сначала воспроизвели дефект: 8 ожиданий
  STALE/BLOCKED получили OK.
- После исправления обе операции (`prepare`, `prepare_initial`) возвращают
  STALE при смене каталога и BLOCKED при STOPPED/HUMAN; одновременная смена
  выбирает BLOCKED. Эффекты текущей транзакции отсутствуют.
- Собственные тесты без DSN: PASS, 57 discovered, 50 выполнено, 7 PG-тестов
  пропущено по отсутствию DSN в этом прогоне.
- CP0: PASS; защищённые файлы 140/140.
- CP1: PASS, 19/19.
- CP2: PASS: PG_GATE before/after на одних данных с реальным restart и 7/7
  собственных PostgreSQL-тестов, включая три обязательных process-сценария.
- Новый patch применён к чистой выданной базе; семь выходных файлов совпали по
  SHA-256, тесты и CP1 из этой копии прошли.
- CP3: NOT_RUN — ответственный интегратор; нужны принятые production owner-
  адаптеры и общий runtime.
- CP4: NOT_RUN — ответственный независимый аудитор; нужна установленная
  интегрированная система и результаты CP3.

Это готовый возврат исполнителя, но не заявление о приёмке полной системы.

## Состав

- `solution/first_materials_runtime/` — модуль, CP2-адаптер и SQL;
- `tests/first_materials_runtime/` — unit и process/PG-тесты;
- `integration_proposal/B8-04.patch` — полный патч к выданной базе;
- `evidence/` — команды, коды выхода и сырые логи;
- `REQUIREMENT_MAP.md`, `CHANGELOG.md`, `CONNECTION_AND_ROLLBACK.md`;
- `RESULT.json` и `SHA256SUMS.txt`.

В архив не входят DSN, пароль, `.cp2-venv`, данные PostgreSQL, `.vscode`, кэши
и отчёты прежних возвратов.
